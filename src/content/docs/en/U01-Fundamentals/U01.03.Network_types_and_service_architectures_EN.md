# U01.03 — Network Types and Service Architectures

> **Guiding question:** What are we describing when we say that a network is a LAN, WLAN, public, private, client-server, or P2P?

The same network can have several correct descriptions at the same time. The common mistake is not using labels, but **mixing different criteria** as if they belonged to a single classification.

For example, a school network may be:

- a **LAN** because of its scope;
- a **WLAN** in the part where devices connect through Wi‑Fi;
- a network with **guest access**;
- a network that uses **client-server** services;
- an infrastructure with services distributed across several systems.

The key is to ask first:

```text
Which criterion am I using?
```

---

# 1. Classification by scope

Classification by scope describes the approximate area covered by the network.

| Type | Approximate scope | Example |
|---|---|---|
| **PAN** | personal area | connection between nearby devices |
| **LAN** | home, classroom, office, or building | classroom or floor network |
| **CAN** | several nearby buildings | school or university campus |
| **MAN** | metropolitan area | municipal network |
| **WAN** | distant locations | organization sites in different cities |

These boundaries are approximate. The important point is to understand scale and context.

In this module, two ideas will be especially important:

```text
LAN
→ local communication inside an organization

WAN
→ communication between distant networks or access to external networks
```

---

# 2. WLAN

A **WLAN** is a local network that uses wireless communication for part of its access.

```text
laptop
  ))) Wi‑Fi
      AP
       |
     switch
       |
    server
```

WLAN does not mean that the whole network is “Wi‑Fi only.” A wired infrastructure may connect access points, switches, servers, and routers.

Therefore:

```text
LAN
→ describes local scope

WLAN
→ indicates wireless access inside a local network
```

---

# 3. Public, private, and guest access

“Public” does not necessarily mean “everything is open.” It may refer to the fact that certain people can connect to or use a specific part of the network.

A library may offer Wi‑Fi to visitors and, at the same time:

- block access to staff computers;
- keep internal servers protected;
- apply usage policies;
- maintain control of the infrastructure.

Key idea:

```text
being able to connect
≠
having access to every resource
```

This distinction prevents a common misunderstanding: allowing access to a network or service is not the same as removing controls, permissions, or administration.

---

# 4. Client and server are roles

A **client** requests a function or resource.

A **server** provides a function or service.

Example:

```text
browser
→ requests a page
→ web server
```

Another example:

```text
PC
→ queries a name
→ DNS server
```

We should not think:

```text
client = laptop
server = rack-mounted machine
```

Client and server are **roles in an interaction**. The same system can act as a client in one communication and as a server in another.

---

# 5. Client-server architecture

In a client-server architecture, several clients request resources or functions from a central service.

```text
clients
   ↓
central service
```

Common advantages:

- centralized administration;
- more consistent permissions;
- better organized data and backups;
- easier monitoring.

Main dependency:

- if the central service fails, many users may be affected;
- redundancy may be required;
- the incident can have a broad scope.

---

# 6. Peer-to-peer architecture: P2P

In a **peer-to-peer (P2P)** architecture, participants can directly provide and consume resources.

```text
PC-A ↔ PC-B
```

It may be useful in small or specific contexts, but it can make these tasks harder:

- centralized administration;
- consistent permissions;
- backups;
- control;
- availability.

P2P is not “always bad,” and client-server is not “always better.” The decision depends on needs, scale, control, availability, and administration.

---

# 7. Distributed services and dependencies

An application that appears to the user as a single function may depend on several systems.

```text
client
   |
   v
web server
   |
   +-- authentication
   +-- database
   +-- storage
```

These components may be located:

- on the local network;
- at another site;
- in a data center;
- in cloud services.

Important idea:

> The more dependencies a service has, the more important it is to determine which part works and which part does not.

A DNS, authentication, or database failure may prevent an application from being used even if other components are still powered on.

---

# 8. Summary

To classify a network correctly:

```text
first: criterion
second: label
third: justification
```

Key ideas to keep:

- LAN, CAN, MAN, and WAN describe scope.
- WLAN describes local wireless access.
- Public does not mean unrestricted.
- Client and server are roles.
- P2P allows direct exchange between participants.
- An application may depend on several services.
- A symptom does not automatically prove the cause.

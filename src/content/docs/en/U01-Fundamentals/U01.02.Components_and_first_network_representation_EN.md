# U01.02 — Components and first network representation

## 1. Why we start by identifying components

Before configuring a network, it is important to know **which elements exist**, what role each one performs, and how they relate to each other. In a real network, saying “there are several connected devices” is not enough: we need to distinguish devices, interfaces, media, links, and services.

In this session, Packet Tracer is used as an observation tool. The goal is not to configure anything yet, but to learn how to read a topology with initial technical criteria.

## 2. End devices

**End devices**, also called *hosts*, are systems where communications used by applications or users originate or terminate.

Common examples include:

- PC;
- laptop;
- smartphone;
- tablet;
- server;
- printer;
- IP camera;
- virtual machine.

A server can be an end device. Being powerful or providing services does not automatically make it an intermediary device. The key is the role it performs in the communication being analyzed.

## 3. Intermediary devices

**Intermediary devices** connect, forward, route, or facilitate communication between other devices.

| Device | Initial role |
|---|---|
| **Router** | Interconnects different networks and allows traffic to continue toward other destinations. |
| **Switch** | Connects devices inside a wired local network. |
| **Access point / AP** | Allows wireless clients to connect to the network. |
| **Firewall** | Applies policies to allow or block specific flows. |

In U01, we only need to recognize the general role. We are not studying MAC tables, routes, VLANs, NAT, or wireless security yet.

## 4. Device, interface, medium, and link

These four concepts should not be mixed up.

| Concept | Useful question | Example |
|---|---|---|
| **Device** | Which system or piece of equipment participates? | router, switch, AP, PC |
| **Interface** | Through which point does the device connect? | Ethernet port, Wi‑Fi interface |
| **Medium** | Through what does the signal travel? | copper, fiber, air/radio |
| **Link** | What connection joins two interfaces? | connection between a PC and a switch |

Summary:

```text
device ≠ interface ≠ medium ≠ link
```

A device may have several interfaces. A link connects interfaces. The medium allows the signal to propagate.

## 5. Reading a topology without copying it

A Packet Tracer topology is already a representation. During a first reading, there is no need to copy it on paper or rebuild it in another tool. What matters is learning to reduce it mentally:

```text
Which end devices appear?
Which intermediary devices appear?
Which links connect the main parts?
Which element seems central for a specific communication?
What can I observe, and what can I not conclude yet?
```

In the file used in this session, we know that there are **2 routers, 1 switch, and 1 AP**. The exact names, links, and interfaces must be read directly from the `.pkt` file; they should not be invented.

## 6. Packet Tracer as a source of visual evidence

Packet Tracer allows us to observe a topology, but a visual observation does not prove every possible cause.

Example:

```text
I see an inactive link.
```

That may be a valid observation. But it does not automatically prove:

```text
The router is broken.
```

Additional tests would be needed to prove a cause. In U01, this rule is enough:

```text
observation ≠ hypothesis ≠ proven cause
```

## 7. What remains for later units

Later units will cover:

- IP configuration;
- technical selection of media and cabling;
- internal switch operation;
- routes and router administration;
- VLANs;
- wireless security;
- detailed traffic analysis.

In U01, the goal is more basic and very important: **look at the network in an organized way before touching it**.

# U01.02 — Componentes y primera representación de una red

## 1. Por qué empezamos identificando componentes

Antes de configurar una red, conviene saber **qué elementos existen**, qué función cumple cada uno y qué relación mantienen entre sí. En una red real no basta con decir «hay varios equipos conectados»: necesitamos distinguir dispositivos, interfaces, medios, enlaces y servicios.

En esta sesión se utiliza Packet Tracer como herramienta de observación. El objetivo no es configurar, sino aprender a leer una topología con criterio técnico inicial.

## 2. Dispositivos finales

Los **dispositivos finales** o *hosts* son sistemas en los que se originan o terminan comunicaciones utilizadas por aplicaciones o usuarios.

Ejemplos habituales:

- PC;
- portátil;
- teléfono móvil;
- tablet;
- servidor;
- impresora;
- cámara IP;
- máquina virtual.

Un servidor puede ser un dispositivo final. Que sea potente o proporcione servicios no lo convierte automáticamente en dispositivo intermediario. La clave es la función que cumple en la comunicación que estamos analizando.

## 3. Dispositivos intermediarios

Los **dispositivos intermediarios** conectan, reenvían, dirigen o facilitan la comunicación entre otros dispositivos.

| Dispositivo | Función inicial |
|---|---|
| **Router** | Interconecta redes diferentes y permite que el tráfico continúe hacia otros destinos. |
| **Switch** | Conecta dispositivos dentro de una red local cableada. |
| **Punto de acceso / AP** | Permite que clientes inalámbricos se conecten a la red. |
| **Firewall** | Aplica políticas para permitir o bloquear determinados flujos. |

En U01 solo necesitamos reconocer la función general. No estudiamos todavía tablas MAC, rutas, VLAN, NAT ni seguridad inalámbrica.

## 4. Dispositivo, interfaz, medio y enlace

Estos cuatro conceptos no deben mezclarse.

| Concepto | Pregunta útil | Ejemplo |
|---|---|---|
| **Dispositivo** | ¿Qué equipo o sistema participa? | router, switch, AP, PC |
| **Interfaz** | ¿Por qué punto se conecta el dispositivo? | puerto Ethernet, interfaz Wi‑Fi |
| **Medio** | ¿Por dónde viaja la señal? | cobre, fibra, aire/radio |
| **Enlace** | ¿Qué conexión une dos interfaces? | conexión entre un PC y un switch |

Resumen:

```text
dispositivo ≠ interfaz ≠ medio ≠ enlace
```

Un equipo puede tener varias interfaces. Un enlace conecta interfaces. El medio permite que la señal se propague.

## 5. Leer una topología sin copiarla

Una topología de Packet Tracer ya es una representación. En una primera lectura no hace falta copiarla en papel ni reconstruirla en otra herramienta. Lo útil es saber reducirla mentalmente:

```text
¿Qué dispositivos finales aparecen?
¿Qué dispositivos intermediarios aparecen?
¿Qué enlaces conectan las partes principales?
¿Qué elemento parece central para una comunicación concreta?
¿Qué información puedo observar y qué todavía no puedo concluir?
```

En el archivo usado en esta sesión sabemos que aparecen **2 routers, 1 switch y 1 AP**. Los nombres exactos, enlaces e interfaces deben leerse directamente en el archivo `.pkt`; no deben inventarse.

## 6. Packet Tracer como fuente de evidencia visual

Packet Tracer permite observar una topología, pero una observación visual no demuestra cualquier causa.

Ejemplo:

```text
Veo un enlace inactivo.
```

Eso puede ser una observación válida. Pero no permite afirmar automáticamente:

```text
El router está averiado.
```

Para demostrar una causa harían falta pruebas adicionales. En U01 nos basta con aprender esta regla:

```text
observación ≠ hipótesis ≠ causa demostrada
```

# U01.03 — Tipos de red y arquitecturas de servicio

> **Pregunta guía:** ¿Qué estamos describiendo cuando decimos que una red es LAN, WLAN, pública, privada, cliente-servidor o P2P?

Una misma red puede recibir varias descripciones correctas al mismo tiempo. El error habitual no es usar una etiqueta, sino **mezclar criterios distintos** como si pertenecieran a una única clasificación.

Por ejemplo, una red de centro educativo puede ser:

- una **LAN** por su alcance;
- una **WLAN** en la parte donde los equipos acceden por Wi‑Fi;
- una red con **acceso de invitados**;
- una red que utiliza servicios **cliente-servidor**;
- una infraestructura con servicios distribuidos en varios sistemas.

La clave es preguntar primero:

```text
¿Qué criterio estoy usando?
```

---

# 1. Clasificación por alcance

La clasificación por alcance describe la extensión aproximada de la red.

| Tipo | Alcance orientativo | Ejemplo |
|---|---|---|
| **PAN** | entorno personal | conexión entre dispositivos próximos |
| **LAN** | vivienda, aula, oficina o edificio | red de un aula o de una planta |
| **CAN** | varios edificios próximos | campus educativo |
| **MAN** | zona metropolitana | red municipal |
| **WAN** | ubicaciones alejadas | sedes de una organización en ciudades distintas |

Estas fronteras son orientativas. Lo importante es comprender la escala y el contexto.

En este módulo serán especialmente importantes:

```text
LAN
→ comunicación local de una organización

WAN
→ comunicación entre redes alejadas o acceso a redes externas
```

---

# 2. WLAN

Una **WLAN** es una red local que utiliza comunicación inalámbrica en parte de su acceso.

```text
portátil
  ))) Wi‑Fi
      AP
       |
     switch
       |
    servidor
```

WLAN no significa que toda la red sea “solo Wi‑Fi”. Puede existir una infraestructura cableada que conecte puntos de acceso, switches, servidores y routers.

Por tanto:

```text
LAN
→ describe alcance local

WLAN
→ indica acceso inalámbrico dentro de una red local
```

---

# 3. Red pública, privada y acceso de invitados

“Público” no significa necesariamente “todo abierto”. Puede referirse a que determinadas personas pueden conectarse o utilizar una parte concreta de la red.

Una biblioteca puede ofrecer Wi‑Fi a visitantes y, al mismo tiempo:

- impedir acceso a ordenadores del personal;
- mantener servidores internos protegidos;
- aplicar políticas de uso;
- conservar el control de la infraestructura.

Idea clave:

```text
poder conectarse
≠
tener acceso a todos los recursos
```

Distinguir esto evita una confusión frecuente: permitir acceso a una red o servicio no equivale a eliminar controles, permisos o administración.

---

# 4. Cliente y servidor son roles

Un **cliente** solicita una función o recurso.

Un **servidor** proporciona una función o servicio.

Ejemplo:

```text
navegador
→ solicita una página
→ servidor web
```

Otro ejemplo:

```text
PC
→ consulta un nombre
→ servidor DNS
```

No debemos pensar:

```text
cliente = portátil
servidor = máquina de rack
```

Cliente y servidor son **roles en una interacción**. Un mismo equipo puede actuar como cliente en una comunicación y como servidor en otra.

---

# 5. Arquitectura cliente-servidor

En una arquitectura cliente-servidor, varios clientes solicitan recursos o funciones a un servicio central.

```text
clientes
   ↓
servicio central
```

Ventajas habituales:

- administración centralizada;
- permisos más consistentes;
- datos y copias mejor organizados;
- supervisión más sencilla.

Dependencia principal:

- si el servicio central falla, puede afectar a muchos usuarios;
- puede ser necesario diseñar redundancia;
- la incidencia puede tener alcance amplio.

---

# 6. Arquitectura entre iguales: P2P

En una arquitectura **peer-to-peer (P2P)**, los participantes pueden ofrecer y consumir recursos directamente.

```text
PC-A ↔ PC-B
```

Puede ser útil en contextos pequeños o concretos, pero puede dificultar:

- administración centralizada;
- permisos homogéneos;
- copias;
- control;
- disponibilidad.

P2P no es “siempre malo” y cliente-servidor no es “siempre mejor”. La decisión depende de necesidades, escala, control, disponibilidad y administración.

---

# 7. Servicios distribuidos y dependencias

Una aplicación que el usuario percibe como una única función puede depender de varios sistemas.

```text
cliente
   |
   v
servidor web
   |
   +-- autenticación
   +-- base de datos
   +-- almacenamiento
```

Estos componentes pueden estar:

- en la red local;
- en otra sede;
- en un centro de datos;
- en servicios cloud.

Idea importante:

> Cuantas más dependencias tenga un servicio, más importante será delimitar qué parte funciona y cuál no.

Un fallo de DNS, autenticación o base de datos puede impedir usar una aplicación aunque otros componentes sigan encendidos.

---

# 8. Síntesis

Para clasificar correctamente una red:

```text
primero: criterio
segundo: etiqueta
tercero: justificación
```

Ideas que debes conservar:

- LAN, CAN, MAN y WAN describen alcance.
- WLAN describe acceso inalámbrico local.
- Público no significa sin restricciones.
- Cliente y servidor son roles.
- P2P permite intercambio directo entre participantes.
- Una aplicación puede depender de varios servicios.
- Un síntoma no demuestra automáticamente la causa.

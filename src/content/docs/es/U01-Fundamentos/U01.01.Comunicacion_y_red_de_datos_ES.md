# U01.01 — Comunicación y red de datos

## 1. Punto de partida

Una red no debe entenderse al principio como una colección de cables, iconos o comandos. Antes de configurar nada conviene comprender qué problema resuelve: permite que sistemas y aplicaciones intercambien información.

Cuando una persona envía una fotografía, abre una web o descarga un archivo, el usuario percibe una acción sencilla. Sin embargo, para que esa acción funcione deben intervenir varios elementos: participantes, información, medios de transmisión, representación de la señal y reglas compartidas.

Ejemplo visible para el usuario:

```text
persona A
→ fotografía
→ persona B
```

Pero la comunicación real necesita más estructura que esa representación simplificada.

---

## 2. Elementos básicos de una comunicación

Una comunicación, en sentido general, implica al menos los siguientes elementos.

| Elemento | Función | Ejemplo |
|---|---|---|
| **Emisor** | Origina la información | Un teléfono que envía una fotografía |
| **Receptor** | Recibe la información | El teléfono de destino |
| **Mensaje** | Información intercambiada | Texto, imagen, audio, vídeo o datos de una aplicación |
| **Canal o medio** | Permite transportar la señal | Cobre, fibra óptica o radio |
| **Codificación** | Representa físicamente la información | Señal eléctrica, óptica o radioeléctrica |
| **Protocolo** | Define reglas para que los participantes se entiendan | Ethernet, IP, TCP, HTTPS |

Estos elementos no siempre aparecen de forma visible para el usuario. El usuario puede ver únicamente una aplicación, un botón o una página, pero debajo existe una comunicación organizada.

### 2.1. Emisor y receptor

> El **emisor** es quien origina una información en una comunicación concreta. El **receptor** es quien la recibe.

No deben confundirse necesariamente con personas. En redes, el emisor y el receptor pueden ser aplicaciones, servicios, equipos o interfaces, según el nivel de detalle con el que estemos analizando la comunicación.

Por ejemplo:

```text
navegador
→ solicita una página
→ servidor web
```

En esa interacción, el navegador inicia una petición y el servidor web responde. En otra comunicación distinta, ese mismo equipo podría cumplir otro papel.

### 2.2. Mensaje

> El **mensaje** es la información que se intercambia. Puede ser algo que el usuario reconoce directamente, como un archivo PDF, una imagen o un texto, pero también puede ser información técnica necesaria para que el servicio funcione.

En esta primera sesión no necesitamos analizar todavía todos los mensajes internos. Basta con comprender que la comunicación transporta información y que esa información debe ser representada de alguna forma para viajar por el medio.

### 2.3. Medio o canal

> El **medio** o **canal** es aquello que permite transportar la señal entre dispositivos o interfaces.

Ejemplos iniciales:

| Medio | Tipo de señal habitual |
|---|---|
| Cobre | Eléctrica |
| Fibra óptica | Óptica |
| Aire | Radioeléctrica |

Una misma comunicación completa puede atravesar varios medios. Por ejemplo, un portátil puede conectarse por Wi‑Fi a un punto de acceso y, desde ahí, la infraestructura puede continuar por cable de cobre o fibra.

### 2.4. Codificación

Para que la información viaje por un medio debe representarse físicamente. Esa representación puede ser eléctrica, óptica o radioeléctrica, entre otras posibilidades.

En U01 basta con entender la idea general:

```text
información
→ representación física
→ señal que viaja por un medio
```

El estudio detallado de tecnologías, conectores, fibra, radio, velocidades, interferencias y calidad del canal se desarrollará en U03.

### 2.5. Protocolo

> Un **protocolo** es un conjunto de reglas que permiten que los participantes de una comunicación intercambien e interpreten información de forma compatible.

Un protocolo no es simplemente el nombre de una tecnología. Define aspectos como:

- qué información se intercambia;
- cómo se organiza;
- cuándo se envía;
- cómo se interpreta;
- qué debe hacerse ante determinadas situaciones.

Ejemplos de protocolos que aparecerán a lo largo del módulo:

```text
Ethernet
IP
TCP
UDP
DNS
DHCP
HTTP/HTTPS
SSH
```

En U01 solo necesitamos reconocer que existen reglas compatibles. El funcionamiento por capas, la encapsulación, las PDU, las cabeceras y el análisis formal de tráfico se desarrollarán en U02.

## 3. Medio no es protocolo

Una confusión habitual al comenzar redes es mezclar el canal físico con las reglas de comunicación.

```text
medio
→ transporta o permite propagar la señal

protocolo
→ define reglas para intercambiar e interpretar información
```

Un cable de cobre no es un protocolo. Una señal radioeléctrica no es un protocolo. Del mismo modo, IP o TCP no son cables ni ondas: son reglas y mecanismos lógicos que permiten organizar la comunicación.

Ejemplo:

```text
cable Ethernet de cobre
→ medio físico

Ethernet como tecnología de enlace
→ reglas de comunicación en ese enlace
```

En la práctica profesional ambos aspectos están relacionados, pero conviene diferenciarlos desde el principio porque resuelven preguntas distintas.

---

## 4. ¿Qué es una red de datos?

> Una **red de datos** es un sistema organizado de dispositivos, interfaces, medios, protocolos y servicios que permite intercambiar información entre aplicaciones y sistemas.

Por tanto, una red no es simplemente:

```text
varios ordenadores + cables
```

Una red puede incluir:

- ordenadores;
- portátiles;
- teléfonos móviles;
- servidores;
- impresoras;
- teléfonos IP;
- cámaras;
- sensores;
- máquinas virtuales;
- switches;
- routers;
- puntos de acceso;
- firewalls;
- interfaces físicas y virtuales;
- enlaces de cobre, fibra o radio;
- servicios como DNS, DHCP, autenticación, almacenamiento o monitorización.

Una red profesional no solo debe conectar equipos. También debe poder administrarse, ampliarse, protegerse, supervisarse y mantenerse con un nivel de servicio adecuado.

---

## 5. Red e Internet no son lo mismo

Una red puede existir sin acceso a Internet.

Ejemplo:

```text
PC ── switch ── servidor local
```

Si el PC puede acceder al servidor local, existe una red local funcional aunque no haya salida a Internet.

Internet es una interconexión mundial de redes administradas por organizaciones diferentes. Puede ser un destino externo o un conjunto de redes externas a las que queremos llegar, pero no es la definición de red.

Modelo simplificado de acceso a Internet:

```text
PC
 │
switch
 │
router
 │
proveedor
 │
Internet
```

Por tanto:

```text
red ≠ Internet
```

Esta diferencia es importante para diagnosticar problemas. Si una persona dice «no tengo red», puede querer decir muchas cosas distintas:

- no tiene enlace físico;
- no tiene Wi‑Fi;
- no obtiene dirección IP;
- no llega a su gateway;
- no resuelve nombres;
- no abre una aplicación concreta;
- no tiene acceso a Internet.

Cada una de esas situaciones requiere observaciones diferentes.

## 6. Expansión de las redes y aparición de dependencias

Las redes se han expandido porque cada vez más funciones dependen de la comunicación digital:

- web;
- correo;
- mensajería;
- videoconferencia;
- bases de datos;
- aplicaciones empresariales;
- almacenamiento;
- servicios cloud;
- administración remota;
- IoT;
- virtualización;
- teletrabajo.

Pero más servicios también significan más **dependencias**.

Una aplicación aparentemente sencilla puede depender de varios elementos:

```text
cliente
→ red local
→ gateway
→ proveedor
→ DNS
→ servidor
→ base de datos
```

Este esquema no debe interpretarse como una ruta universal ni como una explicación completa de todos los protocolos que intervienen. Es un mapa inicial de dependencias posibles.

Si una aplicación no funciona, todavía no podemos afirmar automáticamente cuál es la causa. El fallo podría estar en el equipo del usuario, en la red local, en un servicio de nombres, en un enlace externo, en el servidor, en la base de datos o en una política de acceso.

Por eso, desde el inicio del módulo conviene diferenciar:

```text
síntoma observado
≠
causa demostrada
```

---

## 7. Primer criterio profesional: observar antes de concluir

Un error frecuente consiste en saltar directamente desde un síntoma a una causa.

Ejemplo:

```text
"No se descarga el PDF"
→ "El servidor está caído"
```

Esa conclusión puede ser cierta, pero no está demostrada solo por el síntoma.

Un razonamiento más prudente sería:

```text
síntoma: no se descarga el PDF
hecho: todavía no se ha obtenido el archivo
hipótesis posible: puede existir un problema en el servidor
otras hipótesis: DNS, conectividad, autenticación, permisos, navegador, red local...
siguiente paso: obtener una evidencia más concreta
```

Durante el módulo aprenderemos a convertir síntomas en investigaciones ordenadas. En esta primera sesión basta con fijar una idea:

> Una conclusión técnica solo puede ser tan fuerte como la evidencia que la sostiene.

---

## 8. Síntesis

Al terminar este apartado debes poder explicar que:

- una comunicación necesita participantes, información, medio o canal, representación y reglas compatibles;
- un protocolo define reglas de comunicación, mientras que un medio permite transportar una señal;
- una red de datos es un sistema organizado, no solo un conjunto de cables o equipos;
- una red puede existir sin acceso a Internet;
- el crecimiento de los servicios aumenta las dependencias;
- un síntoma no demuestra por sí solo una causa concreta.

Mapa final:

```text
comunicación
│
├── emisor
├── receptor
├── mensaje
├── medio/canal
├── codificación
└── protocolo

red de datos
│
├── dispositivos
├── interfaces
├── medios
├── protocolos
└── servicios

operación inicial
│
├── observar
├── distinguir qué funciona y qué falla
├── evitar conclusiones precipitadas
└── buscar evidencia
```
